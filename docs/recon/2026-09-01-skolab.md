## 1. What this repository is

- **SkoLab** (aka Entroπ / Skolab) is a **research discovery and career-analytics
  platform for individual academic researchers**. It enriches a researcher's
  public OpenAlex profile with derived metrics (h-index trajectory, disruption /
  novelty scores, collaboration graph), and layers AI features on top: a
  personalised daily paper feed, a "Horizon" emerging-direction engine, grant /
  industry matching, similar-researcher discovery, and a CoLab workspace.
- **Three clients, one backend:** a Jetpack Compose **Android** app (primary,
  ships first), a Next.js 16 **web** app (desktop companion), and a shared design
  system. A **Go gateway** fronts a **Python/FastAPI** AI backend.
- Maturity: **advanced prototype / late MVP.** Large, coherent, heavily iterated
  feature set; real architecture decisions recorded in `decisions/`. Not yet
  production-grade — no deployment target, CI is partly red, test coverage is
  uneven, and there is at least one committed secret.

## 4. What is done (works, or claimed working with evidence in `LOG.md`)

- **Backend enrichment core** — author search, profile enrichment, radar metrics,
  h-index trajectory, similar-researchers (rebuilt to derive peers from
  authorships per `decisions/0005`), two-tier caching, circuit breakers.
- **Recommendation engine** — self-hosted `bge-small` embeddings, pool-mean
  centering, embedding-driven relevance gate, dismiss/feedback loop. Heavily
  iterated (`LOG.md` 07-13 → 07-22).
- **AI features** — daily feed, daily conjecture (single-paper prompt fix),
  Horizon prediction, journal advisor (grounded in real OpenAlex sources),
  industry/grant matching (profile-grounded scoring), agent chat.
- **Web client** — all main routes built, per-section independent data fetching,
  motion token system, KaTeX math rendering with repair pipeline, error banners
  with retry, command palette.
- **Go gateway** — routing, CORS, per-IP rate limiting, circuit breaker,
  leaderboard SQL path, websocket hub; **auth now fails closed in release**
  (`firebase.go`, `decisions`/`LOG.md` 08-09).
- **Android client** — ~40 screens, NSD/mDNS backend discovery, encrypted prefs,
  design-token system, typography harmonised.
- **Data layer** — Alembic initial schema + data-quality constraints migration;
  encrypted column type for user records.
- **SRE scaffolding** — Prometheus/Grafana/Alertmanager configs, k6 suite,
  runbook tooling, synthetic probe, threat-model tests.
- **Security hygiene tooling** — `detect-secrets` pre-commit + baseline, ruff,
  bandit, pip-audit wired into `verify.yml`.

## 7. What cannot be verified from this pass

- **Whether the backend suite actually passes** — no local `pytest`; CI job that
  would prove it is red for an unrelated reason.
- **Whether `next build` / `tsc --noEmit` are currently clean** — nothing runs
  them; last manual check was 2026-07-29.
- **Whether Alembic migrations apply cleanly** to a fresh DB — no CI step.
- **Whether the Go gateway + Python backend actually interoperate end-to-end** —
  requires both running with real Firebase + Postgres + Groq credentials.
- **Runtime behaviour of any AI feature** — needs live API keys.
- **mypy / bandit / pip-audit current results** — reported historically, not
  re-run here.

Blast radius of changing anything blind: the web app and Android app share
Firestore documents directly (no schema enforcement), so a field-shape change on
one client silently breaks the other. The daily-feed candidate pool is
deliberately heterogeneous (arXiv dicts imitating OpenAlex shape) — any consumer
that assumes the OpenAlex schema will 500 the whole request.

## 8. Open questions (for a human — not research tasks)

1. **What is the deployment target?** Nothing in the repo names one. The
   `.claude/rules/` say Cloudflare + Supabase free tier, but the code assumes
   self-hosted Postgres + Firebase + a LAN backend. Which is it for v1?
2. **Is the capability-layer migration meant to be committed now, or reverted?**
   161 uncommitted paths and the deleted knowledge docs need an explicit call.
3. **Is Android or web the v1 launch client?** `PLAN.md` says Android ships
   first; web is further along in `LOG.md`. CI green-lights neither.
4. **Should the three CI workflows be consolidated?** Two are permanently red and
   not required; `checks.yml` is green but shallow. One coherent pipeline would
   remove the "red main is normal" signal.
5. **Firebase Web app registration** — blocked on console access; only the owner
   can do it. Without it the web app has no auth.
6. **Python version** — pin says 3.10; local dev is on 3.14. Pick a supported
   range and fix the `test_threat_modeling.py` teardown before the pin moves.
