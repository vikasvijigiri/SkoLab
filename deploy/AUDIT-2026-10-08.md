# Backend audit and road to 10/10 — 2026-10-08

Scope: the Go gateway (`services/backend-go`), the internal FastAPI service
(`services/backend`), the production image and the Render blueprint.

## Score

| | Before | After this change | With the roadmap below |
| --- | --- | --- | --- |
| Overall | 8/10 | 9/10 | 10/10 |

What keeps it at 9 is no longer code quality. It is two deployment
facts and one product decision: compiles still run beside the API's secrets,
the service is a single free-tier instance, and deleting an account silently
deletes workspaces other people collaborate in.

## How this was verified

Everything ran locally against real dependencies, not mocks:

- Python: `ruff`, `mypy`, `pytest` on Postgres 16 + pgvector with TeX
  installed — 169 passed, 0 skipped, 85% coverage (floor 70%).
- Go: `go vet`, `gofmt`, `go test -race` on the same Postgres with TeX —
  all packages pass, 81.3% coverage (floor 80%; was 80.5%).
- Both processes booted and driven over HTTP and WebSocket: readiness,
  profile sync, workspace CRUD, idempotency replay/mismatch, pagination,
  invites, members, 404/405/413 contracts, single-use tickets, origin
  allow-list, cross-workspace ticket reuse.
- LaTeX sandbox attacked with denylist bypasses (see below).

Not verified here: the Docker image build, the Hurl/Schemathesis staging
suite and Firebase-backed flows. CI's `staging` job covers them.

## Fixed in this change

1. **Removed or demoted editors kept working invite links (authorization
   bug).** Editors may mint links. Removing an editor did not revoke them, so
   the editor could accept their own link and come back as editor. Reproduced
   against the real schema.
   Fix: a link is usable only while its creator is still the owner or an
   active editor (checked in SQL on preview, accept and list), and removing or
   demoting a member revokes their links in the same transaction, so a later
   re-promotion does not revive them.
   Test: `TestSharing_LinksDieWithTheirCreatorsAuthority` (fails on the old
   code).
2. **Compile quota charged for compiles that never ran.** The gateway charged
   4 units before calling the backend; a down, busy or failing backend still
   cost the user. `quota.Charge` now returns a `Receipt` and the compile
   handler refunds it on any backend failure. A compile that actually ran
   (even a LaTeX error or a timeout) stays charged.
   Tests: `TestRefundReturnsTheChargeToBothWindows`, `TestPostgresRefund`,
   `TestFailedBackendCallsAreRefunded`.
3. **The sandbox tests could not detect a leak.** The existing "reads no
   server files" test only proved the keyword denylist refuses `\input`. The
   denylist is trivially bypassed (`\csname input\endcsname`, catcodes), and a
   leaked file is invisible in a compressed PDF. New tests in both
   implementations bypass the denylist on purpose and use a secret that prints
   a marker into the log when read. They pass on the real sandbox and fail when
   kpathsea's `openin_any`/`openout_any` is weakened to `a`.
   Tests: `TestRealCompileContainsDenylistBypasses` (Go),
   `test_real_compile_contains_denylist_bypasses` (Python).
4. **Python logs were unreadable.** The phone-number mask matched any run of
   five or more digits, so IPs, ports, latencies and epoch timestamps became
   `[MASKED_PHONE]`. Phone masking now requires phone shape (`+` prefix or the
   3-3-4 grouping) and a standalone number; bearer tokens are masked first.
   Test: `tests/test_log_masking.py`.
5. **WebSocket consistency.** Upgrade errors now use the standard
   `{"code","error"}` body. The hub drops a workspace's entry when its last
   (slow) client is evicted, which used to leak one map per workspace. Comments
   that described the retired `?token=` flow, and the hub's "OTHER clients"
   claim (the sender does receive its own message), now match the code.
   Test: `TestHub_DroppingTheLastSlowClientForgetsItsWorkspace`.

## Roadmap to 10/10

Ordered by risk removed per unit of effort.

### 1. Compile outside the API container (infra; high)

Today, with `COLAB_SANDBOX_URL` unset, `pdflatex` runs as the same Unix user,
in the same container, as the process holding `DATABASE_URL`, the Firebase
service account and `INTERNAL_API_TOKEN`. The environment is scrubbed and
kpathsea blocks file access (verified above), but a memory-safety bug in the
TeX engine would reach every secret through `/proc`.

- Deploy `cmd/colab-sandbox` as a Render private service with no secrets but
  `INTERNAL_API_TOKEN`, then set `COLAB_SANDBOX_HOSTPORT` and
  `COLAB_REQUIRE_SANDBOX=true` on the API (startup already refuses the
  combination without a worker).
- Give the worker no outbound network and a read-only root filesystem.
- Then delete the Python compile path. It is a second copy of the sandbox
  that must be kept in sync, and it re-verifies the Firebase token (so it never
  works in local dev).

Done when: production `readyz` shows the sandbox in use, and the
Python `/colab/compile` route and its tests are gone.

### 2. Decide account deletion for shared workspaces (product; high)

`DELETE /api/v1/users/{id}` cascades to every workspace the user owns,
including ones with active editors. Their work disappears without notice.
Recommended:

- `POST /workspaces/{id}/owner` to transfer ownership to an active member.
- Account deletion answers `409 owns_shared_workspaces` (listing them) until
  each is transferred or deleted explicitly; solo workspaces still cascade.

Done when: the endpoint and the 409 contract are in OpenAPI, with a
Postgres integration test proving collaborators keep their workspace.

### 3. Leave the single free-tier instance (infra; medium)

`render.yaml` runs one free instance, so there are cold starts and every deploy
is an outage window. The code is already multi-instance ready: Redis-shared
limits, locks and broadcasts, plus `SHARED_STATE_REQUIRED` fail-closed.

- Move to `deploy/render-ha.yaml`: two or more paid instances, Redis
  (`SHARED_STATE_REDIS_URL`) and `SHARED_STATE_REQUIRED=true`.
- Run migrations as a pre-deploy step (`SKIP_STARTUP_MIGRATIONS=1`) so
  replicas never race them.

Done when: a rolling deploy under the k6 load test drops no requests.

### 4. Separate runtime and migration database roles (infra; medium)

Already noted in `deploy/PRODUCTION-HARDENING.md`: the app connects as the
table owner. A runtime role with DML only on its own tables bounds the damage
of any SQL bug.

### 5. Close the remaining test gaps (code; low)

- Extract `main()` into a testable `run(ctx, env)` in both Go binaries (0%
  today), then raise the Go floor from 80% to 85%.
- Add an HTTP-level test for invite accept after member removal (the
  store-level test exists).

### 6. Audit-log retention after account deletion (compliance; low)

`security_audit_log` deliberately has no foreign key, so `actor_id` and `ip`
outlive a deleted account. Write down a retention period and pseudonymize or
purge rows older than it in the existing maintenance loop.

## Kept as is, on purpose

- The keyword denylist stays as a cheap first refusal with a clear error. The
  security boundary is kpathsea's paranoid mode plus `-no-shell-escape`, and
  the new tests pin that boundary.
- Broadcasting to the sender too: changing it would break any client that
  relies on the echo for ordering. It is now documented instead.
